# 인수인계: 0ERROR 예지보전 발표 대본 작업

Claude Code에서 이 작업을 이어받을 때 가장 먼저 읽을 문서. 이전 대화(claude.ai)에서 정한 내용을 정리했다.

## 1. 상황

- 발표: 아주대 자작자동차 연구회 A-FA의 발표. 앞 파트는 "CFD 자동화를 통한 배터리 팩 저비용 열관리 최적화"(Ansys Simulation Challenge 2026), 뒤 파트는 이를 사업화한 공장 냉각설비 예지보전 시스템 "0ERROR(제로에러)".
- 사용자 담당: 예지보전 파트 중 **실현성 → 경쟁 우위 → 사업성 → 기대효과** (슬라이드 5장, 약 6분). 팀 소개는 제외.
- 사용자 선호: 전문 용어는 쉬운 말로 풀어서 설명.

## 3. 대본 작성 원칙 (사용자가 정함)

- 합니다체. 해요체("~인데요", "~거든요", "~죠")는 쓰지 않는다.
- 격식은 지키되 AI가 쓴 것처럼 보이면 안 된다. "첫째·둘째·셋째" 같은 기계적인 나열이나 정해진 틀 같은 문장은 피한다.
- 기존 슬라이드 순서와 화면 구성(왼쪽·가운데·오른쪽)에 맞춘다.
- 분량은 약 6분. 한국어 발표 기준 분당 약 300음절로 계산한다.

## 4. 원본 대비 고친 사실관계 (되돌리지 말 것)

- **ROI 265% → "투자비의 약 2.6배".** (850 − 320) ÷ 320 = 166%가 실제 ROI이고, 265%는 850 ÷ 320 = 2.66배를 잘못 쓴 것이다.
- **매출 손실 방어 문장:** 800만 원 × 35% + 50만 원 = 330만 원 > 320만 원. 잃은 매출의 약 34% 이상이 이익이면 고장 한 번을 막는 것으로 본전을 넘는다.
- **"유일한 진단" 삭제.** 원프레딕트는 운전 인자도 쓰고, 울랄라랩도 온도·압력 센서를 붙이며 냉동설비 모니터링을 제공한다. 차별점은 센서 종류가 아니라 '냉각 회로 물리 모델 + CFD 고장 사전 → 원인 구분'이다.
- **"구독료 전액 순이익" → "수익을 낼 수 있다".** "설치 즉시 가동" → "짧은 보정만으로 바로 운영".
- **"센서만 바꾸면 그대로 적용" → "산업용 센서로 바꾸고 한 번 보정".**
- **용어:** '발열 성능 저하' → '방열 성능 저하', '하이앤드' → '하이엔드', '유랑' → '유량'.

## 5. 아직 팀 확인이 필요한 것

- 실현성 ② 그래프가 실제 주행 로그인지, 테스트베드 재현인지. "즉시 정지했다"는데 그래프는 고장선까지 이어진다.
- 계측 개념도에 냉각 센서(온도·유량·압력)가 빠져 있다.
- 센서 100개 100만 원(개당 1만 원)이 시제품 기준인지. 산업용 센서 단가와 맞지 않는다.
- 로드맵상 AI 검증은 11월 예정인데, 발표에서는 이미 검증된 것처럼 말한다. 완료된 것과 예정인 것을 구분해야 한다.
- 팀 소개에 '남선우'가 두 번 나온다. 원래 발표문에서는 팀장을 '김지윤'으로 소개한다.

## 6. 슬라이드에 남아 있는 수정 필요 사항 (요약)

- AMOP 풀이 오류: 'Adaptive Multi-Objective Optimization' → 'Adaptive Metamodel of Optimal Prognosis' (브리지, 솔루션 ②, CFD Applications 슬라이드).
- 기대효과: '36초 사이클 → 시간당 200개'는 틀렸다(실제 100개). 시간당 200만 원이 공장 전체 기준인지 사출기 5대 기준인지도 섞여 있다.
- 오타: 'C. 0EEROR', '자작자동자', '기술아이디어 부분', 'B2B 영엉'.
- 통계 출처: ABB 원문 수치는 69%다. '3~5배'는 Siemens 보고서에 없는 수치다.
